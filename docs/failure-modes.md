# Failure modes

Every way this system can go wrong that I could name, the control that stops it, how the failure shows up,
and the test or evaluation case that proves the control works. Test paths are relative to `backend/`; `eval:`
names a case in `backend/evals/dataset/`. CI fails if an id here is not traced to a test or a case.

## What the controls do not cover

- The capability token guards against code-path mistakes and approve-then-change. It does not protect against
  a compromised server, which holds the signing secret.
- In the public demo anyone can approve through the demo personas; separation of duties is real between
  personas, not between people.
- The hash chain lives in the same database as the data it protects. It detects an edited, reordered or
  deleted entry, but not the removal of the newest entries or a rewrite of the whole chain: both need the head
  anchored outside the database (a transparency log or a write-once bucket), which production would add.
- Screening for injection is a heuristic. A missed injection still cannot cause an unapproved change: the
  model can only propose, and the policy and a human dispose.
